Every morning

Which PRs need me? Did I already comment? Has the diff moved since?

viii. The sandbox
CH · V · §2
Defence in depth

The PR brings untrusted text. Two flags keep it harmless.

Branch names, Jira tickets, issue bodies — all upstream content gets fenced and sanitised before it reaches Claude. The CLI itself runs with a read-only tool surface.

Tool surface

Allowed

Read Grep Glob Bash(gh:*) Bash(git:*)

Denied

Bash Write Edit WebFetch WebSearch

And ANTHROPIC_API_KEY never reaches the spawned process — env allowlist drops it.

ix. One extra
CH · VI
A skill that learns the team

/pr-review-mining — turn review history into a house style.

Before any of this could really help, Claude had to know what my team cares about. So a skill walks our PR review comments, clusters the recurring ones, verifies them against today's code, and writes them into CLAUDE.md.

  • Mine. Walks GitHub PR review comments.
  • Cluster. Recurring feedback only.
  • Verify. Against the current codebase.
  • Persist. Appends to CLAUDE.md.

xi. Lessons pressed and dried
finis
What I'd carry forward

Three small lessons.

① Ship the HTML first.

A file:// page is a working spec for the real app.

② Sandbox at the CLI.

Two flags and an env allowlist. The smallest defence that works.

③ Teach the team's voice.

Mined review comments make every future review more relevant.
